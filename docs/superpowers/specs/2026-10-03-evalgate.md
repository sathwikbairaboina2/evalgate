## One line

Evalgate runs an agent eval suite on the PR base and head, posts a score-diff comment, and fails the check when the agent got measurably worse. Its LLM judge is calibrated against human labels (Cohen's kappa).

## Why

Every 2026 AI job description asks for "evals and error analysis". Most teams run evals by hand, or run them in CI without a baseline or a noise model, so prompt changes that make the agent worse still get merged. This repo also backs up the profile thesis, "the model proposes, the deterministic core disposes": the judge proposes verdicts, while a deterministic gate with declared limits (minDelta, alpha, critical cases, fail-closed on errors) decides the merge, and the tests prove that each limit is enforced.

## Users and surfaces

1. **CLI** `evalgate` (Node 24, TypeScript, pnpm), with three commands:
   - `evalgate run <suite.yaml> [--out f.json] [--workdir dir] [--repeats n] [--target-url url]` runs the suite and writes a results JSON (`schemaVersion: 1`). Exit 0 unless there is a usage or config error.
   - `evalgate compare --base b.json --head h.json [--comment c.md] [--min-delta x] [--alpha x] [--case-threshold x]` prints a Markdown PR comment and exits 1 on regression.
   - `evalgate calibrate <labels.yaml> [--out r.md] [--json r.json] [--min-kappa x]` reports judge-human agreement (Cohen's kappa, confusion matrix, raw agreement, disagreements). It exits 1 if kappa is below `--min-kappa`.
   - Exit codes: `0` ok, `1` gate failed (regression, or kappa below the floor), `2` usage, config or input error.
2. **GitHub Action** (`action.yml`, composite) runs head, then base (in a `git worktree`), then compare. It writes the job summary, posts or edits the PR comment, and fails the job on regression.
3. **Examples**: `examples/toy-agent/` holds a deterministic toy support agent (`TOY_AGENT_VARIANT=regressed` simulates a bad change), a deterministic suite and an LLM-judge suite. `examples/calibration/support-labels.yaml` is a 16-item labelled set.

## Suite file (YAML, validated with zod, unknown keys rejected)

```yaml
name: toy-support-agent
target:                       # one of: command | http
  type: command
  command: node               # "node" is replaced with the running node binary
  args: [agent.mjs]
  cwd: .                      # relative to --workdir (default: the suite file's directory)
  env: {}                     # merged over the parent environment
  timeoutMs: 30000
# target: { type: http, url: http://localhost:8787/chat, headers: { Authorization: "Bearer ${TOKEN}" },
#           inputField: input, outputPath: output.text, timeoutMs: 30000 }
judge:                        # optional; defaults apply when any case uses llm-judge
  baseUrl: http://localhost:11434/v1   # env EVALGATE_JUDGE_BASE_URL overrides
  model: qwen3.8:27b                   # env EVALGATE_JUDGE_MODEL overrides
  apiKeyEnv: EVALGATE_JUDGE_API_KEY    # name of env var holding the key; never the key itself
  temperature: 0
  timeoutMs: 120000
  extraBody: {}                        # merged into the chat/completions request body
repeats: 1                    # 1..20, per-case score = mean over repeats
concurrency: 4                # 1..32
gate:
  minDelta: 0.02              # aggregate drop that matters
  alpha: 0.1                  # significance level for the paired permutation test
  caseThreshold: 0.5          # per-case delta that marks a case regressed/improved
  permutations: 10000         # Monte Carlo draws when > 16 paired cases
  seed: 42
cases:
  - id: refund-window         # [A-Za-z0-9._-]+, unique
    input: "How long do I have to get a refund?"
    expected: "30 days"       # optional, shown to the judge as reference
    critical: true            # any regression of this case fails the gate
    scorers:
      - { type: contains, value: "30 days" }           # value: string | string[]; all must appear; caseSensitive default false
      - { type: not-contains, value: [STAFF50] }       # none may appear
      - { type: exact, value: "42" }                   # trimmed; caseSensitive default true
      - { type: regex, pattern: "^Hi!", flags: "i" }
      - { type: json-schema, schema: { type: object } } # output parsed as JSON (or first ```json fence)
      - { type: llm-judge, rubric: "PASS if ..." }      # binary verdict
```

## Behaviour

- **Scoring.** Every scorer returns `{score: 0|1, pass, reason}`. A repeat's score is the mean of its scorer scores, and the repeat passes only if every scorer passes. A case's score is the mean over its repeats, and `passRate` is the share of repeats that passed.
- **Errors are not scores.** A target failure (non-zero exit, timeout, HTTP error, missing outputPath) or a judge failure (HTTP error, unparseable verdict) marks the case `error` with `score: null`.
- **Results JSON** is `{schemaVersion: 1, suite, gate, startedAt, finishedAt, cases[], summary{cases, scored, errored, passing, meanScore}}`. `meanScore` is taken over scored cases only.
- **Compare** (gate settings come from the head results, and CLI flags override them):
  - Cases are paired by id. diff = head − base over cases scored on both sides. Aggregate delta = mean(diffs).
  - p-value: one-sided paired sign-flip permutation test (H1: head worse). It is exact for 16 pairs or fewer and uses seeded Monte Carlo above that, so it is deterministic. With no diffs, or all diffs zero, p = 1.
  - Case status: `regressed` if diff ≤ −caseThreshold, `improved` if diff ≥ +caseThreshold, otherwise `unchanged`. Also `added` (only on head), `removed` (only on base), and `error` (null score on either side).
  - **Fails (exit 1)** if any of: (a) any case errored on head (fail closed); (b) any `critical` case regressed; (c) delta ≤ −minDelta with delta < 0 and p < alpha.
  - **Warnings** (do not fail): a drop with p ≥ alpha ("treated as noise"), removed cases, cases that errored on base, and nothing comparable.
- **Comment** starts with the marker `<!-- evalgate -->` and contains: a PASS or FAIL header, a metrics table (mean score, cases passing), the paired delta and p-value, the gate settings, a Blocking list, a Warnings list, a changed-cases table, and a collapsed table of unchanged cases. Signed numbers never print `-0.000`.
- **Judge** calls any OpenAI-compatible `POST {baseUrl}/chat/completions` with temperature 0. It asks for `{"verdict":"pass"|"fail","reason":"..."}`, strips `<think>…</think>`, and extracts the first JSON object. A missing or invalid verdict raises a judge error and is never counted as a pass.
- **Calibration** grades every labelled item one at a time (the model may be a shared local one). Judge errors are counted and left out of the kappa. The confusion matrix has human labels as rows and judge verdicts as columns. Kappa is `null` when expected agreement = 1 (one class only) and renders as "n/a". The report includes a Landis & Koch interpretation and the run duration.

## Non-goals (v0.1)

- No published npm package and no Marketplace listing. The action builds itself from source if `dist/` is missing.
- No stored or cached baselines: base is re-run every time (ADR-0007).
- No graded 1–10 judge scales, logprob scoring, multi-judge ensembles, per-case multiple-comparison correction or bootstrap CIs.
- No HTML dashboard and no trace viewer.

## Acceptance criteria

1. `pnpm install && pnpm typecheck && pnpm test && pnpm build` all succeed on Windows with Node 24, and the unit tests make no network calls (fake judge and fake fetch).
2. Running the toy agent baseline gives mean 1.000 with 10/10 passing. The `regressed` variant gives mean 0.500. `compare` exits 1, naming the 2 critical cases and an aggregate drop with p = 0.0313.
3. Comparing a run with itself exits 0.
4. `calibrate` with a perfect fake judge gives kappa 1.000. With an always-pass judge it gives 0.000, and `--min-kappa 0.6` exits 1.
5. `action.yml` and `.github/workflows/*.yml` parse as YAML, and the CI workflow runs the smoke test (regressed variant must exit 1).
6. The README has: a headline line, a mermaid diagram, a quickstart, a real sample PR comment (generated by the CLI, pasted verbatim), a calibration section with REAL measured kappa or an explicit "not run", and links to the ADRs.
7. `docs/handoff.md` is appended. Nothing is committed or pushed.

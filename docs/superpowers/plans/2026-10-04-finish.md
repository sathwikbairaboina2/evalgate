## Rulings

- Ruling: the PR comment is upserted through the GitHub REST API by a new CLI command `evalgate comment` (find the
  newest comment whose body starts with `<!-- evalgate -->`, PATCH it, else POST). This drops the `gh` dependency and
  makes the logic unit-testable with a fake `fetch`. Recorded as ADR 0008.
- Ruling: the action's bash moves to `scripts/action/*.sh`; `action.yml` only calls them. A vitest e2e test runs those
  scripts against a temp git repo (base commit good, head commit regressed). This is the local stand-in for a real
  GitHub PR run, which stays on the user's list. Recorded as ADR 0009.
- Ruling: lint images are pinned to `rhysd/actionlint:1.7.12` (ShellCheck comes from the same image). If that tag
  cannot be pulled, use the local `rhysd/actionlint:latest` and write a `Ruling:` line with the version it reports.
- Ruling: `evalgate comment` failures (HTTP error, missing token) exit `2` ("input error"); the action step turns that
  into a `::warning::`, so a read-only fork token never fails the job.
- Ruling: the Docker `build` stage installs `git` so the e2e test also runs in `docker compose run --rm test`.
- Ruling: `docs/DEVDOCS.md` is rewritten by the lead in step 5. The builder does not edit it.

## Task 2: Judge parser takes the first JSON object that carries a verdict

Files: `src/judge.ts`, `tests/judge.test.ts`.

- Add `export function extractJsonObjects(text: string): string[]`: scan for balanced `{...}` spans left to right,
  honouring JSON strings and backslash escapes (a `}` inside a string does not close the object). Return the spans in
  order. Unbalanced text yields no span for that start.
- `parseVerdict`: strip `<think>…</think>` as now, then walk the candidates. Use the first one that `JSON.parse`s to an
  object with a `verdict` key. If its verdict is not `pass`/`fail` (case-insensitive) throw `JudgeError` as now. If no
  candidate parses, keep the existing messages ("has no JSON object" when there is no `{`, otherwise "is not valid JSON").
- New tests (write them first, see them fail):
  - `'Note {x}. {"verdict":"pass","reason":"ok"}'` gives pass.
  - `'{"verdict":"fail","reason":"a"} {"verdict":"pass","reason":"b"}'` gives fail (first wins).
  - `'{"verdict":"pass","reason":"uses } and { in text"}'` gives pass with that exact reason.
  - `'{"verdict": "pass"'` (unbalanced) throws `JudgeError`.
  - `'{"note":"no verdict here"}'` throws `JudgeError` (never a pass).
- All existing judge tests stay green.
- Commit: `fix(judge): take the first balanced JSON object that carries a verdict`.

## Task 3: `evalgate comment` upserts the PR comment by its marker

Files: create `src/github.ts`, `tests/github.test.ts`; modify `src/cli.ts`, `tests/cli.test.ts`.

- `src/github.ts`:
  - `export class GitHubError extends Error { name = "GitHubError"; constructor(message: string, readonly status?: number) }`.
  - `export async function upsertComment(opts: { fetch: FetchLike; apiUrl: string; token: string; repo: string; pr: number; body: string }): Promise<{ action: "created" | "updated"; id: number; url: string }>`.
  - Validate `repo` against `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$` and `pr` as a positive integer (else `GitHubError`).
  - If `body` does not start with `COMMENT_MARKER` (import from `report.ts`), prepend `COMMENT_MARKER + "\n"`.
  - List `GET {apiUrl}/repos/{repo}/issues/{pr}/comments?per_page=100&page=N` for N = 1.. until a page has fewer
    than 100 items (stop after 30 pages). Pick the **last** comment whose `body.trimStart()` starts with the marker.
  - Found: `PATCH {apiUrl}/repos/{repo}/issues/comments/{id}` with `{ body }`. Else `POST .../issues/{pr}/comments`.
  - Headers on every call: `authorization: Bearer <token>`, `accept: application/vnd.github+json`,
    `x-github-api-version: 2022-11-28`, `user-agent: evalgate`, and `content-type: application/json` on writes.
  - Non-2xx: throw `GitHubError("GitHub API <METHOD> <path> returned <status>: <first 300 chars>", status)`.
    A thrown fetch: `GitHubError("GitHub API request failed: <message>")`. Strip a trailing `/` from `apiUrl`.
  - Return `{ action, id, url: html_url }` from the response JSON.
- `src/cli.ts`: new command `comment --repo owner/name --pr N --body-file f [--api-url url]`.
  Token from `io.env.GITHUB_TOKEN`; missing or empty is a `UsageError`. `apiUrl` = `--api-url` ?? `io.env.GITHUB_API_URL`
  ?? `https://api.github.com`. Unreadable body file is a `UsageError`. `GitHubError` prints `evalgate: error: ...` and
  returns 2 (no usage text). Success prints `evalgate: comment <created|updated>: <url>` to stderr and returns 0.
  Add the command to `USAGE`.
- Tests (fake `fetch` that records method, url, headers, body):
  - No existing comments: one GET then one POST; the body starts with the marker.
  - Page 1 has 100 non-marker comments, page 2 has a marker comment id 77: PATCH `.../issues/comments/77`.
  - A bot comment without the marker is never PATCHed.
  - Two marker comments: the newer (last listed) one is PATCHed.
  - Body without the marker gets it prepended.
  - Auth, accept and API-version headers are sent.
  - 403 on POST throws `GitHubError` with `status === 403` and the message contains `403`.
  - Invalid repo `"no-slash"` and `pr: 0` throw before any fetch.
  - CLI: missing `GITHUB_TOKEN` exits 2; happy path exits 0 and stderr contains `comment created`; `--api-url` with a
    trailing slash is honoured; 403 exits 2.
- Commit: `feat(cli): upsert the PR comment by its marker through the GitHub REST API`.

## Task 4: Move the action's bash into scripts and fix the base worktree

`scripts/action/post-comment.sh`; modify `action.yml`, `scripts/build.mjs`.

- Every script starts with `#!/usr/bin/env bash` and `set -euo pipefail`, reads only env vars, and keeps the current
  behaviour unless stated. `.gitattributes` already forces LF.
- `evaluate-head.sh`: env `EVALGATE`, `SUITE`, `RUNNER_TEMP`, optional `HEAD_TARGET_URL`.
  Runs `node "$EVALGATE" run "$SUITE" --out "$RUNNER_TEMP/evalgate-head.json"` plus `--target-url "$HEAD_TARGET_URL"` when set.
- `evaluate-base.sh`: env `EVALGATE`, `SUITE`, `RUNNER_TEMP`, `BASE_REF`, optional `BASE_SETUP`, `BASE_TARGET_URL`.
  - Empty `BASE_REF`: print `::error::evalgate: no base-ref given and this is not a pull_request event`, exit 2.
  - Before adding: `git worktree remove --force "$BASE_DIR" 2>/dev/null || true`, `rm -rf "$BASE_DIR"`, `git worktree prune`.
  - `git worktree add --detach "$BASE_DIR" "$BASE_REF"`, then a `trap` that runs `git worktree remove --force "$BASE_DIR"`
    on exit (ignore its failure).
  - Run `BASE_SETUP` inside the worktree as now; then `node "$EVALGATE" run "$SUITE" --workdir "$BASE_DIR/$(dirname "$SUITE")" --out "$RUNNER_TEMP/evalgate-base.json"` plus `--target-url "$BASE_TARGET_URL"` when set.
- `compare.sh`: same logic as the current inline step (env `EVALGATE`, `RUNNER_TEMP`, `GITHUB_OUTPUT`,
  `GITHUB_STEP_SUMMARY`, optional `MIN_DELTA`, `ALPHA`, `CASE_THRESHOLD`). Exit code 0 writes `regression=false`, 1 writes
  `regression=true`, anything else exits with that code. Guard the empty `args` array so `set -u` does not trip on
  bash < 4.4 (`"${args[@]+"${args[@]}"}"`).
- `post-comment.sh`: env `EVALGATE`, `GITHUB_TOKEN`, `GITHUB_REPOSITORY`, `PR`, `FILE`. Runs
  `node "$EVALGATE" comment --repo "$GITHUB_REPOSITORY" --pr "$PR" --body-file "$FILE"`; on failure prints
  `::warning::evalgate: could not post the PR comment (read-only token on a fork PR?)` and exits 0.
- `action.yml`: each step becomes `run: bash "$GITHUB_ACTION_PATH/scripts/action/<name>.sh"` with the same `env:` it has
  now (`EVALGATE: ${{ github.action_path }}/dist/cli.js`). The comment step sets `GITHUB_TOKEN: ${{ inputs.github-token }}`
  instead of `GH_TOKEN`. Add two optional inputs, default `""`:
  - `head-target-url`: "For http targets: URL of the head deployment (passed as --target-url to the head run)."
  - `base-target-url`: "For http targets: URL of the base deployment (passed as --target-url to the base run)."
- `scripts/build.mjs`: accept `--outfile <path>` (default `dist/cli.js`) so tests can bundle to a temp dir.
- Check: `pnpm build && node dist/cli.js --help` still works, and `action.yml` still parses:
  `node --input-type=module -e "import {parse} from 'yaml'; import {readFileSync} from 'node:fs'; console.log(Object.keys(parse(readFileSync('action.yml','utf8')).inputs))"`.
